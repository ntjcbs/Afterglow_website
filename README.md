# Afterglow website

Marketing, support, and privacy pages for Afterglow Music Visualizer for Mac. A plain HTML/CSS site intended for GitHub Pages at [afterglowvisualizer.com](https://afterglowvisualizer.com/). No dependencies, build step, or secrets are required to publish; generated assets are committed.

## Public URLs

Use these URLs in App Store Connect once the domain is live:

| Purpose | URL |
| --- | --- |
| Marketing | https://afterglowvisualizer.com/ |
| Support | https://afterglowvisualizer.com/support.html |
| Privacy policy | https://afterglowvisualizer.com/privacy.html |

## Preview locally

From the repository root, start a local server with Python 3:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Open http://127.0.0.1:8000/. Check all three pages at desktop and mobile widths, including images, navigation, FAQ controls, and the support email link. Stop the server with Control-C.

## Deploy to GitHub Pages

1. Commit and push the site, including [images](images/), [CNAME](CNAME), and [.nojekyll](.nojekyll), to `main`.
2. In the repository's **Settings → Pages**, choose **Deploy from a branch**, branch **main**, folder **/ (root)**, and save. No custom Actions workflow is needed.
3. Set the custom domain to **afterglowvisualizer.com**. Keep [CNAME](CNAME) aligned with this setting.
4. At the DNS provider, remove conflicting parking or URL-redirect records for `@` and `www`, then configure:

	| Type | Host | Value |
	| --- | --- | --- |
	| A | `@` | `185.199.108.153` |
	| A | `@` | `185.199.109.153` |
	| A | `@` | `185.199.110.153` |
	| A | `@` | `185.199.111.153` |
	| CNAME | `www` | `ntjcbs.github.io` |

	Remove any conflicting apex AAAA records, or use GitHub's documented IPv6 addresses. Preserve email-related MX and TXT records. See [GitHub's custom domain documentation](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site) for details; domain verification is recommended.
5. Wait for DNS propagation and GitHub's certificate provisioning, then enable **Enforce HTTPS** in Pages settings.
6. Confirm the Pages deployment succeeds, all three public URLs load over HTTPS, and `www.afterglowvisualizer.com` redirects to the apex domain. Configure and test forwarding for **support@afterglowvisualizer.com** separately; GitHub Pages does not host email.

Subsequent pushes to `main` publish automatically.

## Maintain the site

- Edit [index.html](index.html), [support.html](support.html), and [style.css](style.css) directly.
- [privacy.html](privacy.html) and the images are generated by [scripts/make-site.swift](scripts/make-site.swift) from the separate Afterglow app repository. Update policy text and artwork in that repository, not in generated output. Changes to the privacy page's HTML template belong in the generator.
- Regeneration requires macOS and Xcode with Icon Composer support. It is a maintenance task, **not** part of deployment.

From this repository's root:

```sh
swift scripts/make-site.swift
# Or specify the app repository explicitly:
swift scripts/make-site.swift /path/to/Afterglow
```

The default app repository is `../Afterglow`. The generator reads its privacy Markdown, Icon Composer artwork, and App Store screenshots. Generate screenshots with the app repository's store-media script first; missing screenshots leave the corresponding existing website images unchanged. Review the output and commit regenerated files before publishing.

The home page intentionally says **Coming soon to the Mac App Store**. Once the app is available, replace that label in [index.html](index.html) with the real App Store URL and Apple's official badge.

## Public repository safety

Everything committed here, including Git history, must be suitable for public access. The developer credit, support address, domain, and website artwork are intentionally public. The asset generator contains no credentials and is not executed by GitHub Pages.

- Do not commit credentials, signing keys, environment files, private app source, support correspondence, or account exports. [.gitignore](.gitignore) excludes common sensitive and local files, but does not protect files already tracked or force-added.
- Review staged changes and image contents/metadata before pushing. If Gitleaks is installed, run `gitleaks git . --log-opts="--all" --redact` and `gitleaks dir . --redact` to scan local history and current files.
- Enable GitHub secret scanning and push protection in repository settings where available. No deployment secrets are needed for branch-based Pages publishing.
- For email privacy, enable **Keep my email addresses private** and **Block command line pushes that expose my email** in GitHub's email settings, and configure Git to use the exact GitHub-provided noreply address. This does not change existing commits.
- If a secret is ever published, revoke or rotate it immediately. Deleting the current file or adding an ignore rule does not remove it from Git history, forks, or existing clones.
